# Как вести второй мозг

Правила одинаковы для человека и для ИИ.

## Имена файлов

- Новые файлы: `kebab-case.md` на английском или устойчивом транслите, например `feedback-loop.md`.
- Или читаемое русское название, если так уже названы соседние файлы, например `Русь периода раздробленности.md`.
- Даты только `YYYY-MM-DD`, и дата идёт первой, если важна: `2026-10-19-lecture-03.md`.
- Не использовать `final-final-v2`.
- Существующие файлы не переименовывать без причины: сломаются ссылки `[[...]]`.

## Frontmatter

Для заметок в `wiki/` и служебных заметок обязателен YAML-блок (см. [CLAUDE.md](../CLAUDE.md)). Поля `created` не менять, `updated` обновлять при содержательной правке. Допустимые статусы: `draft`, `needs-review`, `verified`, `archived`.

Личные конспекты в `learning/` могут использовать свой формат.

## Порядок работы

1. **Материал:** положить в `learning/<предмет>/Files/`. После этого не редактировать.
2. **Карточка источника:** `wiki/sources/<slug>.md` по шаблону `source.md`.
3. **Конспект:** в `learning/<предмет>/Lectures/` своими словами.
4. **Понятие:** одна заметка в `wiki/`, сначала обновить `wiki/index.md`.
5. **Проверка:** ссылки открываются, есть `sources:`, факты отделены от вопросов, нет секретов и личных данных других людей.

## Коммиты (если папка под git)

- Один смысл — один коммит. Маленькие коммиты лучше больших «свалок».
- Сообщение в повелительном наклонении: `add source card for lecture 03`, `clarify feedback-loop concept`.
- Перед коммитом проверить: нет токенов и паролей; нет закрытых PDF и сканов, если репозиторий публичный; журналы дописаны, а не переписаны.

## Что не делать

- Не переписывать журналы `x_meta/log/`.
- Не менять содержимое `Files/`.
- Не выдавать сгенерированный ИИ текст за собственную работу.
- Не публиковать чужие материалы, платные учебники и закрытые курсовые данные.
